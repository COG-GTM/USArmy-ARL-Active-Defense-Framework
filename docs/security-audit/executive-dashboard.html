Executive summary

Posture today

  • 17 quick-win mitigations shipped in this PR, gating every unsafe network-deserialization, dynamic-eval, command-exec, and TLS-default path behind explicit operator opt-in env vars (ADF_ALLOW_PICKLE_NET, ADF_ALLOW_EXEC, ADF_MAX_PAYLOAD_BYTES) with one-time WARNING audit logs (NIST AU-2).
  • 7 deferred follow-up tickets filed for architectural work (pickle→JSON, plugin allow-list, control-channel re-architecture) — each tracked as a sub-task under UF-209 with LOC + ACU estimates.
  • 45 compliance + regression assertions wired into CI via tests/test_security_audit.py and tests/test_compliance.py; 0 failures locally.

Why the quick-wins matter

  • The framework's TCP/SSL Listener previously called pickle.loads() on raw network bytes with no length prefix bound — a one-packet RCE if a sender could reach port 42224.
  • Three sites used eval('self.'+method) for IPC dispatch — any caller able to set the IPC method name could pivot to arbitrary code execution inside the framework process.
  • The C BPF tap used strcpy() against argv[5] and an IFNAMSIZ destination — both bounded-overflow candidates that flawfinder flagged at default severity.

Reasoning trace — why these are in-scope quick-wins

  • Env-var gates instead of feature removal. The framework's pickle / eval / exec paths are part of its public surface — flipping them off unconditionally would break existing deployments. A default-deny env-var gate (ADF_ALLOW_*) plus a one-time WARNING log gives operators an audit-grade way to opt in while making the unsafe posture obvious to defenders (NIST AU-2 / SI-10).
  • TLS defaults flipped on, not enforced. The Listener / Sender / control server now build SSL contexts with CERT_REQUIRED + TLSv1_2 minimum by default. Operators can still opt down (e.g. self-signed dev) by passing their own SSL context — but they no longer get a plaintext / unverified channel by accident (NIST SC-8 / SC-13).
  • C strncpy + explicit NUL termination. The bounded-overflow sites in bpf_tap.c are reachable via argv and via the ifr_name kernel string — both untrusted in the threat model. Replacing strcpy with strncpy + a hand-written NUL is a one-line fix that closes the class of bug without touching the BPF data path (NIST SI-10).
  • Architectural items deferred. Replacing pickle framing with JSON, building a typed IPC registry, and signing plugin manifests are all worth doing — but each requires a coordinated rollout against operator deployments and a follow-on test plan, so they're tracked as separate Jira sub-tasks with LOC + ACU estimates rather than crammed into this PR.
